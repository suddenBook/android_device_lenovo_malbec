# Locked upstream input — Lenovo's own corpus for this tablet

`embedding_config.json` is `res/raw/embedding_config.json`, extracted verbatim
from `system/system/framework/framework-res.apk` of the **TB390FU factory ZUI
image this port was built from** (`ZUI_18.0.10.335_260618_ROW`). Pinned by
`../../local_source_lock.json`; the importer verifies its SHA-256 before reading
it.

⚠️ **This is the schema.** The parallel-window rule format this device tree
uses was copied from this file — it is the Huawei `easygo` lineage that OPPO's
`activityPairs` / `transActivities` also descends from. So these 288 rows load
without translation, and every key in them is a key this port already
understands. That is not a coincidence and it is why this file is a better
input than a re-derivation would be.

⚠️ **And it is first-party for this exact hardware.** Everything else in
`../3.01.48/` is a community compatibility module written for Xiaomi tablets.
This is Lenovo's own ruleset, shipped on this model, for this panel. It is dark
on retail units only because `product/etc/build.prop` sets
`ro.config.lgsi.region=row` and `ActivityThread#injectEmbeddingRules` returns
early on that value — the corpus, the patched `androidx.window.extensions.jar`,
`EmbeddingAppService` and the Settings page are all present and intact. See
`work/notes/parallel-window/20-zui-teardown.md`.

**It is a reference, not a golden rule.** Four of the classes its
`com.sina.weibo` row names do not exist in the installed APK, its
`transActivities` carries a meaning this schema splits in two, and two rows
spell `forceFullScreenPages` with a capital S. The importer records every one of
those; see `localUnmappedAttributes`, `localTypoRecoveries` and
`localDividerDefaulted` in `../../hyperos_import_audit.json`.

Do not edit this file. Only the 77 packages `../../local_additions.json` names
are read from it — the other 211 already come from the 3.01.48 conversion.
